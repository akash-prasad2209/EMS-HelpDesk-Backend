# Helpdesk Management System - Backend

ASP.NET Core Web API (.NET 8), layered architecture, JWT + department-scoped RBAC,
built from the LLD Build Spec (see the companion PDF).

## Open in Visual Studio
1. Double-click `HelpDeskSystem.sln` (or File -> Open -> Project/Solution in Visual Studio 2022, 17.8+).
2. Let NuGet restore the packages listed in `HelpDeskSystem.Api.csproj` (automatic on first load,
   or right-click the solution -> Restore NuGet Packages).

## Configure secrets (never committed)
Right-click `HelpDeskSystem.Api` -> **Manage User Secrets**, then paste:
```json
{
  "Jwt": {
    "SigningKey": "a-random-string-of-at-least-32-characters"
  }
}
```
(`appsettings.Development.json` ships a placeholder key only so the project loads without secrets set;
replace it before running anything real.)

## Create the database
The schema exists only as C# right now (`Data/HelpDeskDbContext.cs`) - pick **one** of these two ways
to turn it into an actual database. Both produce the same tables.

**Option A - EF Core migration (recommended, stays in sync with the model automatically)**
Package Manager Console (default project: `HelpDeskSystem.Api`):
```
Add-Migration InitialCreate
Update-Database
```
Or from a terminal in the solution folder:
```
dotnet tool install --global dotnet-ef
dotnet ef migrations add InitialCreate --project src/HelpDeskSystem.Api
dotnet ef database update --project src/HelpDeskSystem.Api
```
This also creates a `Migrations/` folder in the project with the generated C# - check that in
alongside the rest of the code so later schema changes are tracked.

**Option B - run the SQL script directly**
Open `database/schema.sql` in SQL Server Management Studio (or `sqlcmd`) connected to your
LocalDB/SQL Server instance and execute it. Matches the EF model exactly (table names, keys,
FKs, indexes) - useful if you want to inspect or hand the schema to a DBA before the app ever runs.
If you use this option, skip `Add-Migration`/`Update-Database` - running both would try to create
the tables twice.

Either way, point `ConnectionStrings:HelpDeskDb` in `appsettings.Development.json` at the server
you used.

## Run
Press **F5** (or Ctrl+F5) with `HelpDeskSystem.Api` set as the startup project.
Swagger opens automatically in Development at `https://localhost:<port>/swagger`.

On first run in Development, `Program.cs` seeds Roles, Departments, Categories, RequestTypes
and one demo login per role (all passwords: `Passw0rd!`):

| Role | Email |
|---|---|
| Admin | admin@helpdesk.local |
| Employee | employee@helpdesk.local |
| HR | hr@helpdesk.local |
| IT | it@helpdesk.local |

## Try it
1. `POST /api/v1/auth/login` with one of the demo logins -> copy the `token`.
2. In Swagger, click **Authorize**, paste `Bearer <token>`.
3. As `employee@helpdesk.local`: `POST /api/v1/tickets` to raise a ticket under an IT or HR category.
4. As `it@helpdesk.local` or `hr@helpdesk.local`: `GET /api/v1/tickets/queue` - only your department's
   tickets appear. `PUT /api/v1/tickets/{id}/assign` and `/status` to work it.
5. As the original employee: `GET /api/v1/notifications/my` to see the notification generated by the
   status change.
